# 五款游戏扩展

## 范围与顺序

1. 保留 `garden-guard` 原有核心、关卡、存档和交互，迁入独立 workspace，使用共享平台能力与构建工具。
2. 采集四个参考站点的桌面和移动端菜单、操作、战斗/经营、暂停、升级与结算状态；记录需求矩阵。
3. 打通真实 Cocos Creator 3.8 LTS + TypeScript 项目、Web 与微信/抖音原生构建。具体版本与构建方式在工具链验证后锁定。
4. 每款先完成可运行的最小闭环，再逐项补齐参考玩法和画面，分别提交。
5. 大厅增加五款游戏实机封面与介绍，扩展八款游戏的全站及三端检查。
6. 全部检查通过后提交、推送并发布完整站点；核对线上版本和入口，关闭本轮服务。

## 验收约束

- 全部游戏独立目录、pnpm workspace、根锁文件，支持子路径部署。
- 核心规则独立于 DOM、wx、tt；平台差异集中在共享包。
- Cocos 项目须能由对应版本 Creator 打开；记录实际执行的构建路径，区分引擎构建与编辑器导出。
- 微信和抖音使用原生小游戏运行时，不依赖 WebView 或网页大厅；主包预算超出时使用分包。
- 规则测试、构建检查、模拟宿主、开发者工具、真机各自记录，不相互替代。
- 参考与实现使用一致视口/状态对比；MVP 不能作为完整复刻的完成凭据。
