# 幸运弹球的配置证据与重建边界

2026-10-19。来源仍为官网公开 Android 包，URL 见 [配置研究](OFFICIAL-CONFIG-RESEARCH.md)。通过 ZIP 目录和 HTTP 206 范围读取取得 `assets_resources_skilldisp.ab`，没有下载整个安装包。该资源为 904,153 字节，SHA-256 为 `2049e3dcf0ddfcb5cda86a09f9a37ace40c8d11f275fb7deb8d74f050b3e8a04`。只读取序列化设置，没有加载或执行原版程序集。

独立读取器 `tools/inspect-reference-behaviors.py` 校验固定指纹，读取 2,804 个唯一数字名称的行为资源，输出十六组选择性字段，其中三组用于与温压弹、干冰弹和压缩气刃交叉比较。此版本所有 `m_skillDispId` 都是0，资源名称才与 `SubSkillConfg` 尾字段对应。定点字段保留原整数，并明确以除以 `2^32` 的方式显示数值；未识别的枚举保留原值，未启用的联合分支中的默认值不作为生效参数。读取器同时保留自身所需/禁止 Buff 条件，避免把互斥外观分支当成同时发射。

## 已接入的玩法与本地解释

主技能的成功施放累计到6次触发一次品质抽取；普通并发数量、延迟连发、裂变子球、幸运主球和衍生光球均不增加这个计数。毁灭猛击将阈值减至5。每次触发只抽一次品质；弹球浪潮增加的主球沿用该品质。这与主技能事件和子技能分离的配置相符，但原客户端事件发送边界、空目标和对象上限情形尚未实测。

三品质使用100:50:10权重，并沿用本地确定性随机源。主球先准备2.8秒，再飞行5秒，沿原方向穿透目标，撞墙反射；对同一目标至少间隔0.5秒造成伤害。中/高品质命中时每个主球至多每3秒衍生一次光球；高品质同时爆炸。光球不反弹，不递归产生子球或爆炸。终极循环增加幸运主球撞墙爆炸，事件间隔0.5秒。

以下明确属于本地映射，不能声称已复原原版运行结果：

- 战场坐标：主球速度280，低品质半径12，中/高品质18；光球速度560、半径8、最长2秒；高品质爆炸半径64，撞墙爆炸51.2。原版场景单位、不同碰撞枚举和边界布局尚未映射，未直接把原始世界单位作为像素。
- 时间起点：准备结束后才消耗5秒飞行寿命；首个有效命中即可产生衍生攻击，随后按每个主球计3秒。定点数据不能单独证明原客户端的生命周期起点。
- 伤害基数：主球按基础伤害的5倍、光球/高品质爆炸4倍、撞墙爆炸3倍实现，分别对应增量4/3/2。基础伤害38及局外增益合并方式仍是本地调校。普通弹球的局内伤害、数量、体积、必暴和分裂不默认传递给幸运球。
- 对象上限：与其他弹道共享320上限。满额时暂留满充能，等待可发射空间和有效目标；额外主球仅在剩余容量内生成。所有准备、计数、弹道、衍生间隔在暂停/选卡时停止，新局重新计数。
- 原创表现：辉银、耀紫、鎏金的名称、色彩、准备环、金属球和爆炸均为本地绘制；没有复制原版特效、图片、音频或代码。

时间映射采用本地固定60Hz：约0.500000000466秒按最近帧取30帧，浮点寿命在误差小于`1e-8`时到期；这些是明确的离散化选择，不等于原客户端内部比较方式已被观察。新产生的裂变球从下一规则帧开始推进；暂停和三选一期间不消耗寿命、连发等待或目标命中间隔。重复命中计时按每个球的每个目标独立保存，不会阻止同一球击中另一个目标。幸运主球的2.8秒准备、5秒飞行及光球时序继续独立配置。

规则验证覆盖实际发射球的第480帧到期、裂变球第210帧到期、连发第30帧出现、暂停/选卡冻结和两个目标各自的命中冷却；碰撞和计时边界使用隔离规则夹具，导出流程仍只通过正常选择与时间推进取得技能。

## 目标弹射与边界反射

三个计数字段必须分别保留，不能只根据`m_sceneReflectCount=0`推断裂变球不能撞墙反弹。

| 行为 | 目标反弹 / 穿透 | 场景反射 | 回弹 / 范围类型 | 其余相关配置 |
| --- | --- | --- | --- | --- |
| 普通15011 / 钢珠机15221 | 3 / 3，`m_througtReflect=1` | 9999999 | 9999999 / 2 | 目标弹射距离-1，初速度18 |
| 裂变15061 / 15111 | 3 / 3，`m_througtReflect=1` | 0 | 9999999 / 2 | 目标弹射距离-1，初速度14，碰撞半径约0.07；普通球约0.1 |
| 幸运主球15611 | 0 / 99999，`m_througtReflect=0` | 99999 | 99999 / 2 | 持续穿透型的对照 |
| 温压1011 | 0 / 0，`m_througtReflect=0` | 0 | 0 / 2 | 范围类型2本身不足以证明会反弹 |
| 干冰2011 / 气刃6011 | 0 / 3或4，`m_througtReflect=0` | 0 | 0 / 0 | 普通穿透型的对照 |

本地规则现将边界反射与敌人弹射分开。普通球与子球撞战场边界都不扣敌人次数，仍由8秒/3.5秒寿命和共享320弹道上限约束；普通球基础从4次转向修正为3次，按「初次命中后最多再转向3次」处理，因此无其他升级时最多4次敌人命中。弹球浪潮增加2次敌人转向，其他武器的跳跃计数不受影响。距离-1暂映射为全场可选，继续按最近存活目标转向；没有可选目标时沿反方向返回。

裂变球的碰撞半径改为普通基础半径的0.7倍，速度改为基础速度的14/18；像素基数10和320仍是本地映射。子球不继承局内尺寸、速度、必暴或递归裂变。普通球的边界事件按每球0.5秒限制撞墙爆炸/裂变，与15011的事件61间隔一致。其`m_count=10`的调度语义尚未确认；未把它解释成一次产生10个子球。钢珠机的同一事件间隔实际为0，当前尚未实现该分支。

碰撞算法按当前帧剩余时间依次处理最近的圆形表面接触或边界接触，再沿改变后的方向继续运动。球不再瞬移到敌人中心，也不再用反射前后端点的直线代替实际路径。不同体型敌人按表面先后命中；同时接触按敌人ID稳定排序，角点同时反射两个速度分量。每球每帧最多处理32次接触，避免零时间接触循环；现有合法升级的目标预算小于该上限。

这些是基于具名字段和交叉配置的重建解释，尚未通过原客户端确认枚举、首次命中是否计入次数、场景反射对象、目标排序或事件61调度。连续碰撞、帧内排序及数值容差是本地算法；静态配置不证明原版使用相同算法。实际规则测试覆盖边界不扣次数、有限寿命、距离超过260的目标转向、边角真实路径、不同体型的首次接触、裂变相对尺寸/速度及边界事件间隔。三端流程额外记录同一存活弹球撞墙前后命中数不变且剩余次数不变的证据。

21点自动获得隐藏词条、当前卡池/研究调度、钢珠机、动能强化和超武装尚未复原。

## 隐藏分支待核实

隐藏分支已有下一步线索：BuffAttr150112 的参数包含6、21、15000、150113；150113包含84、7、2002、3、1、5000。组2002实际包含1518–1521、1524和1553「幸运增伤」，前五项疑似权重100、上限1，1553疑似权重10、上限99；浪潮还要求 `(4,15000,10)`。权重表中组2002在0–30各行均有100。读取器已保留这些记录，下一步需核实类型84/86及参数的实际调度含义，不能直接把这六项作为普通升级池，或把静态存在当作已经运行过隐藏选卡。

新增分支也不能仅凭名称放入普通池：组1015中钢珠机1522、动能强化1523、超武装1524的`values2To4`均为`[0,0,1]`；它们分别带有`(2,1501,1)`、`(2,1501,1)+(4,15000,14)`、`(2,1517,1)`条件。超武装在隐藏组2002另有`[100,100,1]`记录，升维+1525在组1015为`[60,60,2]`并带`(4,15000,6)`条件。这些直接字段支持区分普通组、隐藏组和条件来源；零值是否由研究或模式动态改写，以及完整条件语义，仍需核实。后续等级表与属性表支持研究6级将1504替换为1525，该分支已接入；31级说明冲突和分组例外见 [冷却与研究应用](RESEARCH-COOLDOWN.md)。

交叉检查提供了更窄的推断范围：Build1600104「天降之物」的说明为获得2个随机词条，其引用的 BuffAttr16001041 以 `(84,1,2)` 开头；Build1600135「天降横财」的说明为所有技能各获得1个随机词条，其 BuffAttr16001351 以 `(84,3,1)` 开头。它们支持类型84与授予词条有关，但不能证明子类型7是弹出选择、自动抽取还是批量授予，也不能解释参数3/1/5000。完整已读记录中 `(86,6)` 仅见于150112，缺少独立同类样本。读取器把这些比较单独输出，保留不确定性；尚未据此改动21点分支。

pnpm --filter zombie-fire reference:inspect
uv run --no-project --with UnityPy==1.25.0 python games/zombie-fire/tools/inspect-reference-behaviors.py
