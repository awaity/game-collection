# 选卡与文本表的结构核对

2026-10-19，针对官网公开 Android 包的本地研究副本继续核对。来源地址和 UnityFS 提取方式见 [配置研究](OFFICIAL-CONFIG-RESEARCH.md)。没有执行原版代码，没有将原版图像、音频、脚本或全量文本加入发布包。

## 已验证边界

离线读取器为仓库独立编写的 Python 工具，输入是已经提取的七个 TextAsset。它校验固定版本的 SHA-256、头部魔数 `0x2def`、总长度和版本1；文本严格按 UTF-8 解码，不用替换字符掩盖错误。头部第五个字段的算法尚未确定，不声称校验和通过。

对每个完整16字节块，按位置做减法、异或与循环右移，然后重排字节。表头、100,613条连续文本和卡牌的变长字符串共同支持这一转换。尾部不足16字节的转换尚未得到证明：工具不返回这些字节，任何跨越边界的完整载荷都不进入有效记录集合。

## 已建立的引用

`BuildConfig` 的首字段为唯一记录ID，第二字段对应 `TextConfig` 中的卡牌名称；图标字符串后的整数对应说明文字。已对电极柱1401–1420、多维弹球1501–1525的45条定义逐条完成引用核对。这45条都位于完整解码区，未使用最后一条残缺载荷。

载荷以说明文字ID后的第一个字节为偏移0。工具输出使用字节偏移命名，避免把推断包装成原版字段名：

| 偏移 | 读取方式 | 已观察到的关联 | 尚未证明 |
| --- | --- | --- | --- |
| 1 | 大端u32 | 电极柱为14000，弹球为15000，与技能分类相符 | 所有玩法的分类与解锁规则 |
| 5–44 | 十个大端u32 | 疑似新增/替换技能引用；如电极柱基础包含14002，相互连线包含14101和14002 | 引用表、每个槽位的含义及应用顺序 |
| 45 | 大端u32 | 增伤/次数等卡牌含连续的编号，疑似属性引用 | 引用表、属性合并、百分比基数与叠加规则 |
| 53 | 大端u32 | 弹球终极及隐藏分支为1，普通分支为0 | 是否表示专用卡池，以及具体触发时机 |
| 66、70 | 两个大端i32 | 数值符号与说明中的幸运增减对应；成对出现不同端点 | 区间是否两端包含，何时取随机值，显示与结算是否使用同一次值 |

`BuildGroupConfig` 的前两个整数与组ID、卡牌ID关联；其后两个整数在同卡不同组间变化，疑似权重，第五个整数疑似可选次数。第5–19与20–34项呈五组三元条件，可见类型2引用卡牌、类型4引用技能分类及等级。正向条件、排除条件和枚举含义仍需客户端或其他配置交叉确认，当前不据此生成运行逻辑。

例如组1014中，延长连线的条件引用超蓄、技能分类14000及数值2，并在后段引用三种相互连线卡；相互连线则引用额外电极、卡牌801以及数值14/26。它们说明完整树含跨技能、研究和互斥关系，不能直接用当前的通用增伤/冷却卡替代。原版全部研究层级仍未实现。

## 新发现的版本差异

以下对比针对本次包内基础卡牌定义，不推断其他模式、强化卡或热更新覆盖后的最终行为。

| 卡牌记录 | 说明/字段事实 | 修正后的重建与剩余差异 |
| --- | --- | --- |
| 1502、1503、1505 | 幸运数值对 `(5,3)` | +3～5，替换旧固定值 |
| 1504 升维 | 幸运数值对 `(10,8)` | +8～10，替换旧+11 |
| 1506–1509 | 幸运数值对 `(6,4)` | +4～6，替换旧固定值 |
| 1510 动能爆破 | 幸运数值对 `(-9,-12)` | -12～-9 |
| 1511 动能裂变 | 说明为增加幸运，数值对 `(8,6)` | 改为+6～8 |
| 1513–1517 | 说明为增加幸运，数值对 `(8,4)` | 改为+4～8 |
| 1518–1521 终极分支 | 幸运数值对 `(2,1)`，存在幸运弹球附加效果 | 改为+1～2；幸运弹球机制未实现 |
| 1519 弹球浪潮 | 弹射次数+2、个数+1、释放次数+1 | 修正弹射次数为+2 |
| 1512 阻滞打击 | 限制50%加速效果，狂暴免疫；幸运数值对 `(-6,-8)` | 只削弱加速增益，不降低基础速度；幸运-8～-6 |
| 1522–1524 | 钢珠机、动能强化、超武装 | 尚未实现 |

组1015中，弹球重击、动能爆破、阻滞打击、终极与隐藏卡的两个疑似权重字段均为0；部分卡有额外条件。其他组选卡数值并不完全相同。旧攻略的“约10点解锁高维、21点选终极”不足以还原当前版本的完整选卡流程，不能在未映射玩法组的情况下把所有已读卡直接放进通用池。

本轮只修正已经能核对的数值端点、符号、弹射次数和阻滞语义。实现按闭区间抽取整数，在可见卡片生成时固定取值，卡片显示增减及选择后点数，选择时不再随机。这是为了支持可计算的21点选择而采用的本地实现，不是已证明的原版随机算法。读取图鉴/快照及暂停不消耗随机数；刷新仍消耗正常次数。10/21点选卡门槛、可选次数和普通卡池沿用旧重建，尚待当前版本实际调度证据；未加入1522–1524或幸运弹球。

阻滞按本地1秒状态实现，裂隙仍延长新状态。将本地召唤/分裂子体原有的+30%速度单独记为加速增益，未受阻滞时保持其速度；基础速度与难度缩放不算加速增益。致残90%减速独立计时，狂暴清除两者；这些状态时长及加速来源划分需原版实测。

## 复核与下一步

使用 Python 3.10+，在仓库根运行：

```bash
pnpm --filter zombie-fire reference:inspect
# 已提取文件存于其他位置时：
python3 games/zombie-fire/tools/inspect-reference-tables.py --input /path/to/extracted-text-assets
```

默认输入为忽略目录 `artifacts/research/zombie-fire/official-config-text/`，输出为同一研究目录的 `validated-tables.json`。不具备原始研究文件时此命令不能执行；工具不会静默联网获取其他版本。未知文件指纹、越界长度、重复ID、无效UTF-8和缺失结束符均导致失败。输出路径必须位于仓库的忽略目录 `artifacts/`。

下一步先映射关卡引用的选择库/组及研究条件，再核对幸运取值与隐藏卡触发，重建原版分支和敌人状态。`LevelBaseConfig` 与命名波次记录的模式、关卡编号和出怪字段仍待映射；13,014条记录不是13,014个主线关卡。线上服务、原作实际试玩、原创视觉一致性、三端实际运行及完整发布继续按原计划验收。
